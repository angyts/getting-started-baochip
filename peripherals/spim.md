# SPI master — synchronous serial communication

**In one sentence:** SPI master lets the Baochip control another chip using a clock, data line(s), and a chip-select signal.

SPI is common for displays, external flash, sensors and other peripherals that need faster or more flexible transfers than a simple two-wire control bus.

## Basic signals

- **SCK/CLK:** clock generated by the master.
- **MOSI/SDO:** data from master to peripheral.
- **MISO/SDI:** data from peripheral to master.
- **CS/CSN:** chip select; usually one select per connected device.

SPI is synchronous: the clock tells the receiver when to sample bits. The two sides must agree on clock polarity, clock phase, bit order and transfer width.

Some SPI controllers support more than one data wire (dual/quad modes), so pin labels and transfer modes must match the peripheral.

## Baochip instances

The autogenerated register index contains four SPI master instances:
- [SPIM0](https://ci.betrusted.io/bao1x/udma_spim_0.html)
- [SPIM1](https://ci.betrusted.io/bao1x/udma_spim_1.html)
- [SPIM2](https://ci.betrusted.io/bao1x/udma_spim_2.html)
- [SPIM3](https://ci.betrusted.io/bao1x/udma_spim_3.html)

It also lists two SPI slave instances, [SPIS0](https://ci.betrusted.io/bao1x/udma_spis_0.html) and [SPIS1](https://ci.betrusted.io/bao1x/udma_spis_1.html). Master and slave are different roles: a master generates the clock and selects the peripheral; a slave responds to a master.

The pinout lists several alternate-function mappings. For example, PB8/PB9/PB10 can serve as SPIM clock/data signals for one instance, while other pin groups are available. Check the exact pin function and chip-select mapping for the chosen instance.

## Practical checks

- Confirm master/slave roles.
- Confirm CS polarity and which CS belongs to the target device.
- Confirm clock polarity/phase (SPI mode).
- Confirm voltage compatibility and ground.
- Keep wires short for fast clock rates.
- Use a logic analyser if a peripheral does not respond; a successful software transfer does not prove the device accepted the command.
